## 1. 디렉토리 구조 원칙

| 디렉토리 | 용도 | 규칙 |
|----------|------|------|
| `~/projects/` | 개발용 소스코드 | `.git` 존재 권장. 실행용 아님. 편집·브랜치 작업 공간 |
| `~/services/` | 프로덕션 배포 | **systemd 서비스가 참조**. 경로 변경 시 서비스 재시작 필요 |
| `~/scripts/` | 유틸리티 스크립트 | cron에서 실행하는 스크립트, 원타임 스크립트 |
| `/opt/hermes-hub/` | 시스템 인프라 | root-scoped. LiteLLM, Hermes Hub. user 서비스와 symlink 체인 금지 |

### ⚠️ 핵심 주의사항

- **`~/services/` 아래 경로는 절대 임의로 변경하지 마세요.** systemd, Nginx가 직접 참조합니다.
- **`~/projects/`와 `~/services/`는 서로 다른 목적**입니다. projects/는 개발용, services/는 배포용.
- **새 프로젝트 추가 시:** `~/projects/<이름>/`에 클론 → 개발 → 배포 시 `~/services/<이름>/`에 배포.

## 3. 서비스 관리 명령

### 3-1. systemd

```bash
# 서비스 상태 확인
systemctl status closepilot-web
systemctl status rails-puma@urlfavorites_2.0
systemctl status rails-puma@yugoss
systemctl status embedding-service
systemctl status solid-queue@urlfavorites_2.0

# 서비스 재시작
sudo systemctl restart closepilot-web
sudo systemctl restart rails-puma@urlfavorites_2.0
sudo systemctl restart rails-puma@yugoss
sudo systemctl restart embedding-service
sudo systemctl restart solid-queue@urlfavorites_2.0

# 서비스 로그
journalctl -u closepilot-web -f
journalctl -u rails-puma@urlfavorites_2.0 -f
```

### 3-2. rails-puma 템플릿 서비스

`rails-puma@.service`는 템플릿으로, `%i` 변수로 인스턴스를 구분합니다.

```bash
# 새 Rails 서비스 추가 시
# 1. ~/services/rails/<app-name>/ 에 앱 배포
# 2. systemctl enable rails-puma@<app-name>
# 3. systemctl start rails-puma@<app-name>
```

### 3-3. 전체 서비스 헬스체크

```bash
for s in closepilot-web embedding-service rails-puma@urlfavorites_2.0 rails-puma@yugoss solid-queue@urlfavorites_2.0; do
  printf "%-40s %s\n" "$s" "$(systemctl is-active "$s")"
done
```

## 7. 새 프로젝트/서비스 추가 절차

### 새 Rails 서비스 추가

1. `~/projects/<app-name>/` 에 소스 클론
2. `~/services/rails/<app-name>/` 에 배포 (capistrano 또는 수동)
3. systemd 활성화:
   ```bash
   sudo systemctl enable rails-puma@<app-name>
   sudo systemctl start rails-puma@<app-name>
   ```
4. Nginx 설정 추가: `/etc/nginx/sites-enabled/<app-name>.hwandam.kr`
5. Cron 필요 시 `~/scripts/`에 스크립트 추가

### 새 Python 서비스 추가

1. `~/projects/<app-name>/` 에 소스 클론
2. `~/services/<app-name>/` 에 배포
3. systemd 서비스 파일 작성: `/etc/systemd/system/<app-name>.service`
4. `sudo systemctl enable <app-name> && sudo systemctl start <app-name>`
