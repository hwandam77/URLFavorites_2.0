### 0.2 v3.5 업그레이드의 DB 안전성 보장 원칙
1. **파괴적 스키마/데이터 변경 제로 (Zero-Destructive Change)**
   - v3.5의 모든 코드 보완 항목은 **기존 테이블·컬럼·인덱스·벡터 데이터를 그대로 유지한 채** 애플리케이션 로직(UseCase/Domain/Integration/Controller/View) 수정만으로 동작한다.
   - `db:drop`, `db:reset`, `db:schema:load`, `TRUNCATE`, `DELETE FROM` 등의 명령은 **절대 실행하지 않는다**.
2. **배포 스크립트의 2중 보호 장치 강제**
   - `bin/deploy urlfavorites` 실행 시 `PROTECTED_CLEAN_EXCLUDES`(`storage/`, `db/*.sqlite3*`)가 적용되어 `git clean`에서 DB 파일이 철저히 제외된다.
   - `--no-db-backup` 플래그 사용을 금지하고, 배포 직전 `/home/hwandam/backups/urlfavorites/<timestamp>-<sha>/sqlite/` 경로에 `sqlite3 .backup` 온라인 스냅샷 백업이 생성되었는지 반드시 확인한다.
3. **배포 전·후 레코드 카운트 교차 검증**
   - 배포 전과 배포 후 아래 원격 검증 명령으로 `favorites`, `analyses`, `analysis_sections`, `collections`, `favorite_embeddings` 행 수가 **단 1건도 감소하지 않았음**을 수치로 증명한다.

### Phase 1: 핵심 기능 버그 및 UI 보완 (v3.5 Core Fixes)

#### 1-1. [B-1] '핀' 카테고리 필터 버그 수정
- **대상**: `app/url_favorites/use_cases/search/favorite_search.rb`
- **현상**:
  ```ruby
  # 현재 코드 (65~66행)
  scope = scope.where(category: @category) if @category.present? && @category != "전체"
  scope = scope.where(pinned: true) if @category == "핀"
  ```
  `@category == "핀"`일 때 `where(category: "핀")`과 `where(pinned: true)`가 동시에 걸려, 실제 카테고리(`AI에이전트`, `백엔드` 등)를 가진 핀 고정 북마크가 전부 제외된다.
- **수정 방안**:
  ```ruby
  if @category == "핀"
    scope = scope.where(pinned: true)
  elsif @category.present? && @category != "전체"
    scope = scope.where(category: @category)
  end
  ```
- **검증**: `test/url_favorites/use_cases/search/favorite_search_test.rb`에 `category: "AI에이전트", pinned: true`인 북마크가 `FavoriteSearch.call(query: nil, category: "핀")` 및 키워드 검색 시 정상 반환되는지 검증하는 단위 테스트 추가.

#### 1-2. [B-2] 컬렉션 수정 예외 처리 및 사이드바 캐시 무효화
- **대상**:
  - `app/url_favorites/use_cases/collections/update_collection.rb`
  - `app/url_favorites/use_cases/collections/create_collection.rb`
  - `app/url_favorites/use_cases/collections/delete_collection.rb`
  - `app/controllers/collections_controller.rb`
- **현상**:
  1. `UpdateCollection`이 `collection.update!(**attrs)`를 사용하여 빈 이름이나 중복 이름으로 수정 시 `Result.new(ok: false)` 대신 `ActiveRecord::RecordInvalid` 예외가 발생한다. 또한 `attrs[:name] = name if name` 조건은 빈 문자열(`""`)이 전달될 때 검증을触发시키되, 실패 시 `@collection` 상태 처리가 일관되지 않다.
  2. `ApplicationController#set_sidebar_data`는 `Rails.cache.fetch('sidebar_collections', expires_in: 10.minutes)`를 사용하지만 컬렉션 CUD 유스케이스에서 캐시를 삭제하지 않아 최대 10분간 사이드바에 변경사항이 반영되지 않는다.
- **수정 방안**:
  - `UpdateCollection`에서 `collection.update(**attrs)`를 사용하고 성공 시 `Rails.cache.delete("sidebar_collections")` 후 `Result.new(ok: true, value: { collection: collection })`, 실패 시 `Result.new(ok: false, value: { collection: collection }, error: collection.errors)`를 반환하도록 수정한다.
  - `CreateCollection`, `DeleteCollection` 성공 시에도 `Rails.cache.delete("sidebar_collections")`를 호출한다.
- **검증**: `test/controllers/collections_controller_test.rb`에 빈 이름 수정 시 `422 Unprocessable Entity` 응답 테스트 및 생성/수정/삭제 직후 `Rails.cache.read("sidebar_collections")` 무효화 검증 테스트 추가.

#### 1-3. [B-3] 검색 `collection_id` 필터 및 시맨틱 검색 N+1 보완
- **대상**:
  - `app/url_favorites/use_cases/search/favorite_search.rb`
  - `app/url_favorites/integrations/search/semantic_client.rb`
- **현상**:
  1. `FavoriteSearch#apply_filters`에 `@collection_id` 조건이 없어 일반 목록 및 FTS 검색 시 `collection_id` 파라미터가 동작하지 않는다.
  2. `SemanticClient#filter_by_collection_id`에서 `m.collection_id == @collection_id`로 비교하여 문자열 `"1"`과 정수 `1` 불일치로 항상 빈 배열이 된다.
  3. `SemanticClient#call`에서 `Favorite.where(id: favorite_ids)` 조회 시 `:analysis`와 `:collection_memberships`를 preload하지 않는다.
- **수정 방안**:
  - `FavoriteSearch#apply_filters`에 `scope = scope.joins(:collection_memberships).where(collection_memberships: { collection_id: @collection_id }) if @collection_id.present?` 추가.
  - `SemanticClient#call`에서 `Favorite.includes(:analysis, :collection_memberships).where(id: favorite_ids).index_by(&:id)`로 변경.
  - `SemanticClient#filter_by_collection_id`에서 `target_id = @collection_id.to_i`로 변환 후 `m.collection_id == target_id` 비교.
- **검증**: `favorite_search_test.rb`와 `semantic_client_test.rb`에 문자열 `collection_id: collection.id.to_s` 전달 시 필터링 동작 테스트 추가.

#### 1-4. [B-4] Reddit 콘텐츠 타입 UI 필터 추가 및 `v3.5` 버전 표기
- **대상**:
  - `app/views/shared/_sidebar.html.erb`
  - `app/views/favorites/index.html.erb`
- **수정 방안**:
  - `_sidebar.html.erb`의 `type_nav` 배열과 `index.html.erb`의 `type_options` 배열에 `Reddit` (`content_type: "reddit"`) 항목을 추가한다 (Warm Archive 디자인 토큰 유지).
  - `_sidebar.html.erb` 상단 브랜드 영역의 버전 배지를 `v3.0` → `v3.5`로 업데이트한다.
- **검증**: 로컬에서 `bin/rails tailwindcss:build` 및 컨트롤러/시스템 테스트 통과 확인.

### Phase 2: DDD 아키텍처 일관성 및 도메인 정합성 강화

#### 2-1. [A-1] 분석 잡 중복 정리 및 `RetryPolicy` 단일화
- **대상**:
  - `app/jobs/analyze_webpage_analysis_job.rb`
  - `app/jobs/analyze_webpage_job.rb`
  - `app/jobs/analyze_youtube_job.rb`
  - `app/jobs/analyze_twitter_job.rb`
  - `app/url_favorites/domain/analysis/retry_policy.rb`
- **수정 방안**:
  - 각 분석 잡에 하드코딩된 `MAX_RETRIES = 3`, `BACKOFF_SECONDS = [ 30, 60, 120 ]`을 `UrlFavorites::Domain::Analysis::RetryPolicy`에 위임하도록 통일한다.
  - **운영 큐 호환성 보장**: 혹시 운영 Solid Queue에 구 클래스명으로 직렬화된 잡이 남아 있을 가능성에 대비해 `AnalyzeWebpageJob < AnalyzeWebpageAnalysisJob` 형태로 얇은 상속 래퍼만 남겨 중복 코드를 제거하면서도 역직렬화 오류(`NameError`)를 100% 방지한다.

#### 2-2. [A-2] GitHub 링크 자동 등록 시 Domain 정책 재사용
- **대상**: `app/url_favorites/use_cases/analysis/run_analysis.rb`
- **현상**: `enqueue_github_links_from_analysis`가 `Domain::Content::GithubLinkExtractor`를 쓰지 않고 별도 정규식을 쓰며, `Urls::Normalizer`·`Urls::SafetyPolicy`·`Urls::CategoryDetector` 없이 레코드를 생성한다.
- **수정 방안**:
  - `UrlFavorites::Domain::Content::GithubLinkExtractor.call(detail_content)`로 URL을 추출하고, 저장소 루트(`https://github.com/<owner>/<repo>`) 형태만 선별한 뒤 `Urls::Normalizer` 및 `Urls::SafetyPolicy.allowed?`를 통과한 링크만 생성한다.
  - 신규 생성 시 `title: url`, `category: UrlFavorites::Domain::Urls::CategoryDetector.call(url, "github")`를 설정하여 스키마/데이터 일관성을 보장한다 (기존 DB에 저장된 즐겨찾기 데이터는 일절 변경하지 않음).
- **검증**: `test/url_favorites/use_cases/analysis/github_link_extraction_test.rb` 실행 및 케이스 보강.

#### 2-3. [A-3] `Favorite#detect_content_type` 도메인 위임
- **대상**: `app/models/favorite.rb`
- **수정 방안**:
